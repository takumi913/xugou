# XUGOU 部署指南

XUGOU 使用一个 Cloudflare Worker 承载前端、HTTP API、Cron、Queue Consumer 和 WebSocket Durable Object。D1 保存业务数据；Queue 只传递状态变化、通知和状态页重建等低频事件。Agent 每秒通过独立上行 WebSocket 把最新轻量指标送入 AgentRoom，网页立即收到广播；本地 Spool 每 60 秒通过 HTTP 批量写入 D1，承担历史、离线判定和断线补偿。

## 1. 创建 Cloudflare 资源

```bash
pnpm exec wrangler d1 create xugou_db
pnpm exec wrangler queues create xugou-jobs
pnpm exec wrangler queues create xugou-jobs-dlq
```

把 D1 的名称和 ID 写入 GitHub Actions Secrets；仓库中的 `wrangler.toml` 保持 `${D1_DATABASE_NAME}` 与 `${D1_DATABASE_ID}` 占位符。

主 Worker 需要以下 Secrets：

```bash
openssl rand -base64 48 | pnpm exec wrangler secret put SESSION_HMAC_SECRET
openssl rand -base64 48 | pnpm exec wrangler secret put AGENT_TOKEN_PEPPER
openssl rand -base64 32 | pnpm exec wrangler secret put NOTIFICATION_KEK
openssl rand -base64 24 | pnpm exec wrangler secret put ADMIN_INITIAL_PASSWORD
```

`ADMIN_INITIAL_PASSWORD` 只在空数据库首次启动时使用，密码至少 12 位。其余三个值上线后保持稳定；通知 KEK 轮换时按 `wrangler.toml` 中的版本和轮换开关执行。

## 2. 配置 GitHub Actions

在 `production` Environment 中配置：

| Secret | 用途 |
| --- | --- |
| `XUGOU_CF_API_TOKEN` | Workers、D1、Queues 和 Durable Objects 的部署权限 |
| `XUGOU_CF_ACCOUNT_ID` | Cloudflare Account ID |
| `XUGOU_D1_DATABASE_NAME` | D1 数据库名称 |
| `XUGOU_D1_DATABASE_ID` | D1 数据库 ID |

推送到 `main` 后，`.github/workflows/deploy.yml` 会依次执行：

1. 完整质量门禁；
2. 应用尚未执行的 D1 migration；
3. 部署 `xugou-app` Worker。

本地检查与部署：

```bash
pnpm install --frozen-lockfile
pnpm run test:all
pnpm run deploy:dry-run
pnpm run deploy
```

## 3. Agent 下载发布

Agent 二进制使用独立 R2 Bucket。发布工作流只写以下对象：

```text
latest/manifest.json
latest/xugou-agent-linux-amd64
latest/xugou-agent-linux-arm64
latest/xugou-agent-darwin-amd64
latest/xugou-agent-darwin-arm64
latest/xugou-agent-windows-amd64.exe
latest/xugou-agent-windows-arm64.exe
```

`latest/manifest.json` 内嵌 Ed25519 签名，不使用分离签名、版本归档或 channel 对象。`Build and Publish Agent` Environment 需要：

| Secret | 用途 |
| --- | --- |
| `AGENT_UPDATE_PUBLIC_KEY` | Base64 编码的 32 字节 Ed25519 公钥 |
| `AGENT_UPDATE_PRIVATE_KEY_B64` | Base64 编码的 Ed25519 私钥 |
| `R2_ACCESS_KEY_ID` | R2 S3 API Access Key |
| `R2_SECRET_ACCESS_KEY` | R2 S3 API Secret |
| `R2_ACCOUNT_ID` | R2 所属 Account ID |
| `R2_BUCKET_NAME` | Agent 下载 Bucket 名称 |

发布 GitHub Release 或手动运行 `.github/workflows/build.yml`，并传入 SemVer。工作流先构建六个平台产物，再更新二进制，最后切换 `latest/manifest.json`。

`download-compat` Worker 目前只把已安装 Agent 访问的 `/channels/stable.json` 以 307 重定向到 `/latest/manifest.json`；R2 中没有 channel 对象。确认所有在线 Agent 均已升级后，可单独下线这条重定向路由。

## 4. 验证

```bash
pnpm exec wrangler d1 migrations list xugou_db --remote
pnpm exec wrangler deployments status --name xugou-app
curl -fsS https://dl.xugou.mdzz.uk/latest/manifest.json
```

Agent 上行使用 Bearer 鉴权的 `/api/v2/agents/live`；状态页下行使用 `/api/v2/status/public/ws`，管理端下行使用 `/api/ws`。三条链路均由 `AgentRoom` Durable Object 提供，实时样本不写 D1，也不消耗 Queue 消息额度。
