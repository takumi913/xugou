# 质量门禁

本文档记录 XUGOU 在提交、合并和单 Worker 部署前执行的检查。

## 1. 安装依赖与依赖一致性

```bash
pnpm install
pnpm peers check
```

日常与 CI 使用根目录统一入口：

```bash
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run test:all
```

`test:all` 额外覆盖 Worker Binding 类型漂移、Workers Runtime、Contract Release/Authorization、Playwright Mock 故障场景与真实 Worker+D1 闭环、Frontend / Backend Build、Deploy Dry Run、生产依赖与 Peer 检查、Agent 启动冒烟、Go Vet/Gofmt、`govulncheck` 和六平台交叉编译；Backend 的 `src`、`tooling`、`scripts`、`test-runtime` 与 Frontend ESLint 均以零 warning 退出，Backend 脚本也进入严格 TypeScript 编译门禁。

仓库使用 `pnpm-workspace.yaml` 管理供应链策略和允许执行安装脚本的依赖。

## 2. Worker 绑定类型

`wrangler.toml` 的 Vars、D1、Assets、Version Metadata 或 Durable Object Binding 变化后执行：

```bash
pnpm run types:worker
pnpm run types:worker:check
pnpm run test:modules
```

生成文件为 `backend/src/worker-env.d.ts`；Secret 类型在 `backend/src/models/db.ts` 中以窄接口补充。

## 3. 数据库迁移

`backend/src/db/schema.ts` 变化后执行：

```bash
pnpm --dir backend run db:generate
pnpm run test:migrations
```

确认 SQL、`backend/drizzle/meta/_journal.json` 和对应 snapshot 一起提交。数据修复使用 `drizzle-kit generate --custom` 生成有账本记录的迁移，再填写 SQL。

`test:migrations` 同时覆盖：

- 旧多用户库逐文件迁移与数据守恒；
- 外键、完整性、敏感数据和关键索引；
- SQL 导出 Preflight；
- `wrangler d1 migrations apply --local` 完整回放及第二次执行无待应用迁移。

## 4. Backend 契约、安全和模块边界

```bash
pnpm run test:contracts
pnpm run test:modules
pnpm run test:security
pnpm --dir backend run build
```

`test:modules` 同时覆盖 Auth/Monitor/Agent/Operations Application Port、v4
`report_id` 契约、Monitor Check、Agent Report、Notification Consumer、Job 租约、
不可变样本、Outbox/Inbox 重投和 DLQ 捕获。Queue 测试使用真实 SQLite 事务语义重复
执行同一 Consumer，校验业务样本、Notification Message/Attempt/Cooldown 和 Failure
Ledger 不重复。

## 5. Frontend

```bash
pnpm --dir frontend exec tsc -b --noEmit
pnpm --dir frontend run lint
pnpm --dir frontend run build
```

目标结果为 ESLint 零 error、零 warning，并成功生成 Vite/PWA 产物。

## 7. 部署门禁

GitHub Actions 按以下五阶段顺序处理同一个 Worker：

1. 导出远程 D1 SQL、Bookmark 并执行只读 Preflight；
2. `wrangler d1 migrations apply --remote`；
3. 再次导出并执行完整性、外键、核心行数与守恒差额 Postflight；
4. 发布 Worker、Assets、Queue Consumer 与同 Bundle Durable Object；
5. 使用专用 `RELEASE_READINESS_TOKEN` 调用受保护 Readiness，结果为最终发布门禁。

手工部署使用相同顺序：

```bash
umask 077
install -d -m 700 .backups
test -n "$D1_DATABASE_NAME" && test -n "$D1_DATABASE_ID"
pnpm --dir backend wrangler:render-config -- \
  --template ../wrangler.toml \
  --output ../.wrangler.production.toml
WRANGLER_CONFIG=.wrangler.production.toml
pnpm exec wrangler d1 time-travel info "$D1_DATABASE_NAME" --json \
  -c "$WRANGLER_CONFIG" > .backups/pre-bookmark.json
pnpm exec wrangler d1 export "$D1_DATABASE_NAME" --remote \
  --output=.backups/xugou.sql -c "$WRANGLER_CONFIG"
pnpm --dir backend migration:preflight -- --sql-export ../.backups/xugou.sql --allow-empty > .backups/preflight.json
pnpm exec wrangler d1 migrations apply "$D1_DATABASE_NAME" --remote \
  -c "$WRANGLER_CONFIG"
pnpm exec wrangler d1 time-travel info "$D1_DATABASE_NAME" --json \
  -c "$WRANGLER_CONFIG" > .backups/post-bookmark.json
pnpm exec wrangler d1 export "$D1_DATABASE_NAME" --remote \
  --output=.backups/xugou-post.sql -c "$WRANGLER_CONFIG"
pnpm --dir backend migration:preflight -- --sql-export ../.backups/xugou-post.sql --allow-empty > .backups/post-preflight.json
pnpm --dir backend migration:postflight -- --mode expand --before ../.backups/preflight.json --after ../.backups/post-preflight.json --output ../.backups/postflight.json
pnpm --dir backend migration:manifest -- \
  --preflight ../.backups/preflight.json \
  --sql-export ../.backups/xugou.sql \
  --bookmark ../.backups/pre-bookmark.json \
  --postflight ../.backups/postflight.json \
  --post-sql-export ../.backups/xugou-post.sql \
  --post-bookmark ../.backups/post-bookmark.json \
  --git-sha "$(git rev-parse HEAD)" \
  --output ../.backups/migration-manifest.json
chmod 600 .backups/*
pnpm run build
pnpm exec wrangler deploy -c "$WRANGLER_CONFIG"
```

最后执行 `git diff --check`，并确认生产 Secrets、Origin 白名单和回滚备份处于预期状态。
